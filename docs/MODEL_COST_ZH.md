## 1. 公司结论（先看这张）

小团队要控成本，推荐 **三级梯子**，不要八个模型平铺着用。

| 档 | 模型 | 谁用、干什么 | 相对 Flash 的大致费用 |
|---|---|---|---|
| **默认（80–90% 流量）** | `qwen3.8-flash` | 全员日常：翻译、润色、纪要、邮件、访视报告、清单 | 1×（基准） |
| **写作** | `qwen3.8-27b` | 方案章节、SOP、发现归纳、风险描述 | 约 **4×** |
| **难题** | `qwen3.8-max` | 法规对读、科学逻辑、长文档一次吃透 | 约 **14×** |
| **代码 / Agent** | `mimo-v2.5-pro` | Codex、脚本、多步工具 | 约 **3×**（远低于 Kimi） |
| **不要当默认** | `kimi-k3` | 仅当 MiMo Pro 与 Max 都失败 | 约 **30×** |
| 备选便宜推理 | `deepseek-v4-flash-0731` | Flash 排队或效果差时 | 闲时约 2×，忙时约 4× |
| 备选强推理 | `deepseek-v4-pro-0813` | 要推理、又不想上 Max/Kimi | 闲时约 5×，忙时约 11× |
| 备选便宜多模态 | `mimo-v2.5` | 看图/轻量 Agent，中文公文仍优先千问 | 约 1× |

**管理规定建议：**

1. 新人默认模型设为 `qwen3.8-flash`。
2. Codex / Claude Code **写明模型**，禁止依赖网关把 `gpt-4o` 转到 `kimi-k3`（那是最贵路径）。
3. `kimi-k3` 不作聊天默认；需要时由医学经理/管理员点头。
4. 试用期也走梯子：免费额度烧在 Max/Kimi 上，额度会很快没，后面立刻开始付费。

## 3. 一问大约多少钱（便于有体感）

假设一次网页问答：**输入 4,000 tokens + 输出 1,000 tokens**（约 2–3 页中文材料进、半页回答出）。

| `mimo-v2.5` | 0.0060 | 0.60 | 和 Flash 同一量级 |

## 4. 按岗位怎么选（结合现有编制）

编制来自公司花名册：医学经理 1、项目经理 1、CRA 3。都是临床/医学侧，不是算法团队。

### 4.1 医学经理（MED001 王丁坤）

典型工作：方案/IB/研究者手册措辞、审稿意见、中英翻译、与临床/CMC 对齐、偶发脚本与 PPT。

| 任务 | 用 | 不要用 |
|---|---|---|
| 邮件、会议纪要、把一段英文摘要成中文 | `qwen3.8-flash` | Max / Kimi |
| 方案某一章、CSR 讨论草稿、SOP 结构 | `qwen3.8-27b` | 整本方案反复进 Max |
| CDE/ICH 条款和方案原文对读、科学机制说不清 | `qwen3.8-max`（一两次即可） | 用 Kimi 写中文公文 |
| 本地脚本、表格清洗、Codex | `mimo-v2.5-pro` | 默认 `kimi-k3` |
| 连续 Agent 失败、超长仓库 | 再试 `kimi-k3` | 日常挂机 |

预算直觉：经理允许少量 Max；但 **翻译和润色走 Flash**，否则试用额度会先被润色吃光。

### 4.2 项目经理（MED003 刘士麟）

典型工作：纪要、计划、风险、供应商沟通、里程碑冲突。

| 任务 | 用 |
|---|---|
| 纪要、催办邮件、周报 | `qwen3.8-flash` |
| 风险登记表述、跨部门说明、会议决议结构化 | `qwen3.8-27b` |
| 方案时间线/入排标准冲突需要「想清楚」 | 先 27b，不行再 `qwen3.8-max` |
| 做表、自动纪要脚本 | `mimo-v2.5` 或 Flash |

项目经理几乎不需要 Kimi。Max 一个月几次足够。

### 4.3 CRA（MED002 李子木、MED004 涂美慧、MED005 王斯）

典型工作：访视报告、query、TMF 文件名/清单、偏离描述、培训记录。量大、重复、中文公文。

| 任务 | 用 |
|---|---|
| 80%：报告套话、清单、翻译、把口语变成监查语言 | **只准** `qwen3.8-flash` |
| 偏离分级、方案相关解释、发现写清楚 | `qwen3.8-27b` |
| 极难的方案条款理解 | 问医学经理，或经理用 Max，CRA 不要自己开 Kimi |
| 患者身份、原始病历、影像号 | **禁止进模型** |

CRA 三人是流量大户。只要把默认锁在 Flash，公司账单就稳。允许 27b，不鼓励 Max，禁用 Kimi 作为聊天默认。

## 5. 为什么不推荐「全都用最好的」

1. **Kimi K3 输出 100 元/百万**，是 Flash 输出价的约 37 倍。Agent 会吐很长的思维链，费用按输出计，最伤。
2. **Max 12/36** 适合「一篇难文」，不适合「一天五十封邮件」。
3. **DeepSeek 快照忙时**接近 Max，却没有千问的中文公文优势；工作时间优先千问。
4. **免费试用不是无限。** 试用期用 Max 刷长文档，额度结束当天账单会跳起来，团队还没养成选模型习惯。
5. 生物医药的质量风险在「胡编法规/疗效」，不在「模型不够旗舰」。Flash + 人工审核，比 Max 无审核更安全、更便宜。

## 6. 建议的公司默认（可当制度贴出去）

1. Open WebUI 默认模型：`qwen3.8-flash`。
2. 写作升级顺序：Flash → 27b → Max。跳级要能说出理由（例如「27b 把入排标准理解错了」）。
3. 编程默认：`mimo-v2.5-pro`；禁止依赖 GPT/Claude 别名（会落到 Kimi）。
4. `kimi-k3`：管理员或医学经理按次使用，不进新人邮件「推荐模型」第一行。
5. 工作日白天 DeepSeek Pro 快照尽量不用。
6. 单次粘贴超过约 2 万字：先 Flash 摘要，再把摘要和争议段落给 27b/Max。
7. 试用额度用尽后：不改梯子，只是开始从账户扣费；管理员在 LiteLLM 看各 `*-CHAT` / `*-AGENT` 消耗。

按上述执行，五人医学/临床小组在试用结束后，正常办公（以 Flash 为主、少量 27b/Max、偶发 MiMo Pro）月费通常可控制在 **数百元人民币** 量级；若默认 Kimi Agent，仅代码通道就可能到 **人均数百、团队数千**。
